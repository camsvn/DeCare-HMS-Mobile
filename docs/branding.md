# Branding assets

How the launcher icon, splash screen and wordmark are produced, and how to regenerate them.
Sources live in `tools/branding/`; generated files live under `assets/images/` (splash inputs)
and `android/app/src/main/res/` plus `ios/Runner/Assets.xcassets/` (platform outputs).

## Colours

| use | value | token |
| --- | --- | --- |
| Splash background, light | `#151D28` | `DsColors.light.shell` |
| Splash background, dark | `#0B1017` | `DsColors.dark.shell` |
| Launcher icon background | `#16142B` | `android/app/src/main/res/values/ic_launcher_background.xml` |
| Wordmark | `#FFFFFF` | `textOnShell` |

The splash deliberately uses the app's shell colour rather than the logo's own disc colour, so the
splash and the first app frame are one continuous surface.

## Launcher icon

The adaptive icon set (`ic_launcher`, `ic_launcher_round`, `ic_launcher_foreground` at every
density, plus `mipmap-anydpi-v26/*.xml` and the background colour) was copied from the original
React Native app on 2026-09-10. It is not generated; to change it, replace the PNGs at every
density and keep the `anydpi-v26` XML pointing at the same names. The manifest declares both
`android:icon` and `android:roundIcon`. iOS still carries the Flutter template icon.

## Splash screen

Generated by `flutter_native_splash` from the `flutter_native_splash:` section of `pubspec.yaml`.
Three inputs:

- `assets/images/splash_logo.png` (768 × 768): the logo mark without its disc, used by Android
  below 12 and by iOS.
- `assets/images/splash_icon_a12.png` (1152 × 1152): the same mark centred on a transparent
  1152 px canvas. Android 12+ masks the splash icon to the inner two thirds of a 240 dp square,
  so the mark must sit inside the centre 768 px or it is clipped.
- `assets/images/splash_branding.png` (800 × 320): the "DeCare HMS" wordmark for the platform's
  branding slot along the bottom edge (200 × 80 dp).

Regenerate the inputs with ImageMagick (`magick` on PATH) from the repository root:

```bash
# Mark without the disc (tools/branding/hms_mark.svg is assets/images/hms_circle.svg with its
# background <circle> removed).
magick -background none -density 600 tools/branding/hms_mark.svg -resize 768x768 assets/images/splash_logo.png
magick -size 1152x1152 xc:none assets/images/splash_logo.png -gravity center -composite assets/images/splash_icon_a12.png

# Wordmark: Poppins Medium (SIL Open Font License, tools/branding/OFL-Poppins.txt), 104 pt, +2 kerning.
magick -size 800x320 xc:none -font tools/branding/Poppins-Medium.ttf -pointsize 104 -kerning 2 \
  -fill white -gravity center -annotate +0+0 "DeCare HMS" assets/images/splash_branding.png
```

Then generate the platform files and restore the portrait lock:

```bash
dart run flutter_native_splash:create
```

**`create` rewrites `AndroidManifest.xml` and drops `android:screenOrientation="portrait"` from
`MainActivity`. Put it back before committing** (the app is portrait-only). Check with:

```bash
grep -c 'android:screenOrientation="portrait"' android/app/src/main/AndroidManifest.xml   # must print 1
```

Verify on a device or emulator by launching from the home screen. On the emulator, starting the
app with `adb shell am start` immediately after a force-stop can show the Android 12 splash
without its icon; that is an emulator quirk, not a resource problem.

## Fonts

The app bundles Inter (`assets/fonts/`) for all UI text. Poppins is used only to render the
wordmark PNG and is not bundled; the font file and its licence sit in `tools/branding/` so the
wordmark can be re-rendered identically.
